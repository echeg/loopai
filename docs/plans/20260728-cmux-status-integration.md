# cmux status integration

## Overview

Показывать работу ralphex в сайдбаре cmux (macOS-терминал на базе Ghostty): спиннер на время прогона,
пилюля с текущей фазой, прогресс-бар по задачам плана, уведомления когда нужен ввод пользователя
и по завершении прогона.

Проблема: при параллельном запуске нескольких ralphex в разных воркспейсах cmux не видно, какой из них
что делает — cmux детектит только агентов с установленными хуками (claude, codex, pi и т.д.), а ralphex
для него невидим. Свои короткие `claude -p` сессии ralphex порождает десятками за прогон, поэтому даже
там, где cmux их замечает, статус мигает и не несёт смысла.

Решение целиком на стороне ralphex: вызовы публичного CLI `cmux`, никаких правок в cmux и никаких
зависимостей на его приватный сокет-протокол. Вне cmux (нет бинаря в PATH или нет `CMUX_WORKSPACE_ID`)
всё превращается в no-op с нулевой стоимостью.

Ключевые свойства:

- **Best-effort.** Индикация не влияет на ход прогона. Любая ошибка вызова `cmux` игнорируется, прогон
  продолжается. Это индикация, а не функциональность.
- **Никаких правок в `pkg/processor`.** События берутся из уже существующих точек: `status.PhaseHolder`
  для фаз, plan-файл для прогресса, `InputCollector` для вопросов.
- **Гарантированная очистка.** `workspace loading` на стороне cmux не имеет TTL: если ralphex умер, не
  сняв спиннер, тот висит в сайдбаре до перезапуска cmux.

## Context (from discovery)

Изучен исходник cmux (`.reference/manaflow-ai-cmux`, shallow clone). Существенное:

**Поверхность интеграции (публичный CLI, правок cmux не требует):**

| Команда | Эффект в cmux |
|---|---|
| `cmux workspace loading on\|off --id ralphex` | спиннер в сайдбаре + лейн воркспейса → `working` |
| `cmux set-status <key> <value> --icon --color --priority` | пилюля-статус в строке таба |
| `cmux clear-status <key>` | снять пилюлю |
| `cmux set-progress <0.0-1.0> --label <text>` | прогресс-бар в сайдбаре |
| `cmux clear-progress` | снять прогресс-бар |
| `cmux notify --title --subtitle --body` | синее кольцо на панели + баннер macOS + запись в панели уведомлений |

**Почему ключ `ralphex`, а не `claude_code`:**
`Sources/Workspace+SidebarStatusVisibility.swift:16` — пилюли с ключом **не** из agent-allowlist
показываются безусловно. Ключи из allowlist (`claude_code`, `codex`, …) наоборот скрываются, если
cmux не видит живой PID соответствующего агента. Свой ключ надёжнее и не конфликтует с claude-статусом.

**Почему `workspace loading`, а не `set-status`, двигает лейн воркспейса:**
Лейн (`todo`/`working`/`needs-attention`/`review`/`done`) считается в
`Packages/macOS/CmuxWorkspaces/.../WorkspaceTaskStatus.swift:18` из живых сигналов, а не из пилюль.
`workspace_loading` с ключом `manual:<id>` ставит настоящий `.running` на панель
(`Sources/TerminalController+ControlSidebarContext.swift:191`) — это единственный путь до реального
сигнала, не требующий agent-allowlist или vault-регистрации.

**Ограничение (принято осознанно):** лейн `needs-attention` требует `set_agent_lifecycle` с
зарегистрированным agent-ключом, а CLI режет его собственным хардкод-списком (`CLI/cmux.swift:3020`,
`:25178`) — доступен только через приватный сокет. Вместо него используем `cmux notify`: синее кольцо
на панели, подсветка таба и `Cmd+Shift+U` дают тот же практический UX.

**Валидация id:** `manual:<id>` — 1-64 символа из `[A-Za-z0-9._-]`, не более 32 разных loader-ключей
на воркспейс (`ControlCommandCoordinator+SidebarWorkspaceLoadingV1.swift:18-21`). `ralphex` подходит.

**Точки в коде ralphex:**

- `pkg/status/phase_holder.go:15` — `OnChange` поддерживает ровно один коллбэк; слот уже занят
  веб-дашбордом (`pkg/web/broadcast_logger.go:47`). Нужен список наблюдателей.
- `cmd/ralphex/main.go:579` `executePlan` — единственная воронка для всех режимов исполнения
  (вызовы на строках 395, 811 из `runWithWorktree`, 1525 после создания плана).
- `cmd/ralphex/main.go:1379` `runPlanMode` — отдельный вход для `--plan`, свой `holder` и
  `InputCollector` (строка 1447 `input.NewTerminalCollector`, 1464 `SetInputCollector`).
- `cmd/ralphex/main.go:1687` `startInterruptWatcher` — force-exit через `os.Exit(1)` на строке 1697.
  **Дефёры там не выполняются**, отрабатывает только переданный `cleanup` (ограничен 2 секундами
  через `runCleanupBounded`).
- `pkg/plan/parse.go:31` `Task.Status` (`pending`/`active`/`done`/`failed`) и `ParsePlanFile` — готовый
  источник `done/total` для прогресс-бара, считать ничего не надо.
- `pkg/status/status.go:24-32` — константы фаз (`PhaseTask`, `PhaseReview`, `PhaseExternalReview`,
  `PhaseExternalEval`, `PhasePlan`, `PhaseFinalize`) для маппинга в текст пилюли.
- `pkg/executor/executor.go:264` `claudeChildEnv` — вырезает только `CLAUDECODE` и `ANTHROPIC_API_KEY`,
  все `CMUX_*` наследуются дочерними процессами. Менять не требуется.

**Паттерны проекта, которым следуем:** интерфейсы на стороне потребителя, table-driven тесты с testify,
`t.Helper()` в хелперах, регекспы компилируются на уровне пакета, комментарии строчными буквами,
один `_test.go` на файл исходника.

## Testing Strategy

- **Unit-тесты**: обязательны для каждой задачи
- **Внешний бинарь `cmux` в тестах не запускается.** `Reporter` вызывает команды через внутренний
  интерфейс-раннер, который в тестах подменяется на фейк, записывающий argv. Тесты проверяют
  сформированный argv, а не поведение cmux.
- **E2E**: у проекта есть playwright e2e для веб-дашборда (`e2e/`). Эта работа UI дашборда не
  затрагивает, новых e2e не требуется. Существующие должны продолжать проходить.
- **Безопасность тестов**: никаких обращений к `~/.config/ralphex/` и к реальному сокету cmux.
  Переменные окружения ставить через `t.Setenv`, файлы — через `t.TempDir()`.

### Форма вызовов

Аргументы передаются как отдельные элементы argv (`exec.CommandContext`), не как строка — экранирование
не требуется, текст с пробелами и юникодом проходит как есть. Целевой воркспейс не указывается: cmux CLI
по умолчанию берёт `$CMUX_WORKSPACE_ID`, который cmux инжектит в каждый свой терминал и который
наследуется дочерними процессами.

### Интервалы и таймауты

| Параметр | Значение | Обоснование |
|---|---|---|
| Таймаут одного вызова `cmux` | 2 с | сокет локальный; висящий вызов не должен тормозить прогон |
| Интервал поллинга плана | 10 с | итерация задачи идёт минуты, чаще незачем |
| Обрезка тела уведомления | 200 рун | баннер macOS больше не покажет |

### Что осознанно не делается

- **Лейн `needs-attention`.** Требует приватного сокета cmux; `cmux notify` даёт эквивалентный UX
  (синее кольцо, подсветка таба, `Cmd+Shift+U`).
- **`cmux todo set`** — зеркалирование чекбоксов плана в чеклист воркспейса. `docs/cli-contract.md:475`
  прямо просит агентов не трогать чеклист без явной просьбы пользователя. Прогресс-бар закрывает ту же
  потребность без вторжения.
- **Конфиг-флаг включения.** Авто-детект по окружению; отдельная настройка не нужна.
- **Логирование ошибок вызовов `cmux`.** Индикация не должна засорять прогресс-файл.

## Post-Completion

*Требует человека и GUI, автоматизации не поддаётся*

**Ручная проверка в живом cmux:**
- Запустить ralphex в терминале cmux, убедиться: появился спиннер, пилюля меняется на переходах фаз,
  прогресс-бар растёт по мере выполнения задач
- Проверить, что после нормального завершения спиннер и прогресс-бар сняты, пришло уведомление
- Проверить очистку по Ctrl+C — как при одиночном (graceful), так и при двойном (force-exit через 5 с)
- Проверить `--plan`: приходит уведомление на вопросе и на готовом черновике
- Проверить одновременный запуск двух ralphex в разных воркспейсах — статусы не путаются между собой
- Проверить работу с `--serve`: и дашборд, и сайдбар cmux получают события фаз
